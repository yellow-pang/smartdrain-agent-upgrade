# PR Documentation

## 1. 실행 조건

사용자가 PR 문서 작성을 명시적으로 요청한 경우에만 사용합니다.

구현 직후 자동으로 PR 문서를 작성하지 않습니다.

다음 작업은 사용자가 직접 수행합니다.

- 실제 Pull Request 생성
- 원격 저장소 push
- reviewer 지정
- merge
- 브랜치 삭제

## 2. 사전 확인

PR 문서를 작성하기 전에 다음을 확인합니다.

```bash
git status --short
git diff
```

추가로 확인할 내용:

- 변경된 파일
- 커밋되지 않은 변경
- 관련 Plans 문서
- 관련 Steps 문서
- 수행한 검증
- 검증 실패
- 알려진 제한사항
- 후속 작업

실제 Git 변경과 Plans, Steps 내용이 다르면 실제 변경을 기준으로 작성하고 차이를 기록합니다.

## 3. 기존 PR 형식 확인

기존 PR 문서가 있으면 다음을 확인합니다.

- 저장 위치
- 파일명 규칙
- 번호 체계
- 제목 형식
- 섹션 순서
- 체크리스트 형식
- 문체

기존 형식을 우선 유지합니다.

## 4. 문서 위치와 이름

기존 규칙이 없으면 다음 경로를 사용합니다.

```text
docs/pr/
```

기본 파일명:

```text
pr-<번호>-<작업명>.md
```

관련 Plans와 Steps가 있다면 같은 번호와 작업명을 사용합니다.

예:

```text
docs/plans/plan-01-dashboard-refactoring.md
docs/steps/step-01-dashboard-refactoring.md
docs/pr/pr-01-dashboard-refactoring.md
```

## 5. PR 문서 목적

PR 문서는 리뷰어가 다음을 빠르게 이해할 수 있어야 합니다.

- 왜 변경했는지
- 핵심 변경이 무엇인지
- 어떤 영역에 영향을 주는지
- 데이터와 실행 흐름이 어떻게 달라졌는지
- 어떤 검증을 수행했는지
- 리뷰 시 무엇을 집중해서 확인해야 하는지
- 알려진 제한이 무엇인지

## 6. 필수 작성 내용

PR 문서에는 원칙적으로 다음 내용을 포함합니다.

1. 작업 배경과 목적
2. 주요 변경 사항
3. 영향받는 범위
4. 영향받지 않는 범위
5. 구현 또는 데이터 흐름
6. 주요 변경 파일
7. 검증 결과
8. 리뷰 시 확인할 부분
9. 관련 Plans 문서
10. 관련 Steps 문서
11. 알려진 제한사항
12. 후속 작업

## 7. 권장 문서 구조

```markdown
# PR 제목

## 1. 작업 배경

## 2. 주요 변경 사항

## 3. 영향 범위

## 4. 구현 흐름

## 5. 검증 결과

## 6. 리뷰 요청 사항

## 7. 관련 문서

## 8. 제한사항 및 후속 작업
```

## 8. 주요 변경 사항 작성

기능 목록만 나열하지 않고 변경 목적과 결과를 함께 작성합니다.

좋은 예:

```markdown
- 시설 변경 시 이전 이미지가 노출되지 않도록 query key와 로딩 상태를 분리했습니다.
```

피해야 할 예:

```markdown
- 컴포넌트 수정
- API 수정
- 타입 수정
```

## 9. 검증 결과

실제로 실행한 검증만 작성합니다.

```markdown
| 검증 항목    | 결과 | 비고                  |
| ------------ | ---- | --------------------- |
| `pnpm lint`  | 성공 | 오류 없음             |
| `pnpm build` | 성공 | production build 완료 |
```

실행하지 못한 검증은 숨기지 않고 이유를 작성합니다.

## 10. 리뷰 요청 사항

리뷰어가 집중해서 볼 부분을 구체적으로 작성합니다.

예:

- 기존 WebSocket payload와 호환되는지
- query cache 갱신 시 중복 렌더링이 없는지
- Alembic migration이 기존 데이터에 안전한지
- callback 재시도 시 중복 저장 가능성이 없는지

## 11. 관련 문서 연결

관련 Plans와 Steps 문서를 상대 경로로 연결합니다.

```markdown
- Plan: `../plans/plan-01-dashboard-refactoring.md`
- Steps: `../steps/step-01-dashboard-refactoring.md`
```

## 12. 작성 금지 사항

- Plans와 Steps를 그대로 복사하지 않습니다.
- 구현하지 않은 내용을 포함하지 않습니다.
- 실행하지 않은 검증을 성공했다고 작성하지 않습니다.
- 확인하지 않은 성능 개선을 주장하지 않습니다.
- 실제 Git diff에 없는 변경을 포함하지 않습니다.
- 알려진 오류나 제한사항을 숨기지 않습니다.

## 13. Git 변경 확인

PR 문서 작성 후 다음을 확인합니다.

```bash
git status --short
git diff -- <작성한 PR 문서>
```

이번 단계에서 작성한 PR 문서 변경만 기준으로 한글 Conventional Commit 메시지를 제안합니다.

실제 commit과 push는 수행하지 않습니다.
